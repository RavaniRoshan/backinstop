Under high load, Backstop's admission control can shed lower-priority requests
to protect latency for critical traffic. You assign a priority to each request
via the `X-Backstop-Priority` header — no per-call code changes needed.

## The three priority levels

Backstop defines three priorities via the `Priority` enum:

```python
from backstop import Priority

Priority.CRITICAL    # user-facing, must not be delayed
Priority.DEFAULT   # standard traffic
Priority.BACKGROUND # batch jobs, analytics, indexing
```

## Marking requests by priority

Set the `X-Backstop-Priority` header on any SDK call:

```python
from openai import OpenAI
from backstop import Backstop

client = Backstop.wrap(OpenAI(), budget=100_000)

# Critical — user-facing request, protected from shedding
response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Generate a response"}],
    extra_headers={"X-Backstop-Priority": "critical"},
)

# Background — batch summarization, can be shed under pressure
response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Summarize last week's logs"}],
    extra_headers={"X-Backstop-Priority": "background"},
)
```

## How admission control works

When too many requests are in-flight (hitting the concurrency ceiling),
Backstop queues incoming requests. The admission gate processes the queue with
this rule:

1. **Critical** requests always pass — they skip the queue or preempt a
   background request.
2. **Default** requests wait behind any queued critical requests.
3. **Background** requests are the first to be shed when the queue grows too
   long. If `starvation_after_seconds` (default: 1.0s) elapses and a background
   request hasn't started, it is rejected with `BudgetExceededError`.

The `starvation_after_seconds` parameter controls how long a request waits in
the queue before being rejected:

```python
from backstop import BackstopConfig

config = BackstopConfig(
    initial_concurrency=4,       # allow 4 concurrent calls
    max_concurrency=16,          # scale up to 16 under light load
    starvation_after_seconds=2.0,  # shed queued requests after 2 seconds
)
```

## Priority-aware fallback chains

You can also route different priorities to different fallback chains:

```python
from backstop import BackstopConfig, Priority

config = BackstopConfig(
    fallback_chain_for_priority={
        Priority.CRITICAL: [
            {"model": "gpt-4o"},
            {"model": "gpt-4o-mini"},  # degraded fallback for critical traffic
        ],
        Priority.BACKGROUND: [
            {"model": "gpt-3.5-turbo"},  # cheaper fallback for batch
        ],
    },
)
```

## Complete example

A full priority admission demo is in
[`examples/background_priority.py`](https://github.com/RavaniRoshan/backstop/blob/main/examples/background_priority.py):

```python
from openai import OpenAI
from backstop import Backstop, BackstopConfig

client = Backstop.wrap(
    OpenAI(),
    budget=100_000,
    config=BackstopConfig(initial_concurrency=8),
)


def user_facing_request(prompt: str):
    return client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": prompt}],
        extra_headers={"X-Backstop-Priority": "critical"},
    )


def background_job(prompt: str):
    return client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": prompt}],
        extra_headers={"X-Backstop-Priority": "background"},
    )
```

## Verification

`backstop verify` includes an isolation check that proves per-agent budgets are
independent — critical for ensuring priority routing doesn't leak budgets:

```text
- [PASS] per-agent isolation: agent A blocked 5/5 at its own cap while agent B kept serving — budgets are independent.
```
